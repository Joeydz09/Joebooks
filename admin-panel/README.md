# Joebooks Admin — Foundation

هذه مجلدات تأسيس لوحة إدارة Joebooks. الواجهة الحالية **نموذج بصري أولي فقط** وليست لوحة تشغيلية.

## الحالة الحالية
- واجهة عربية RTL متجاوبة بهوية كحلي/فضي/ذهبي.
- أقسام مبدئية: الرئيسية، الكتب، التصنيفات، المحتوى اليومي، صفحات الموقع، الملفات والأغلفة، التحليلات، الإعدادات، سجل العمليات.
- لا يوجد اتصال ببيانات الإنتاج، ولا تسجيل دخول في الواجهة، ولا أسرار.
- الأرقام غير متصلة ومتعمدة أن تظهر كشرطات؛ لا تمثل أعداد الموقع.
- يوجد هيكل Worker API للقراءة فقط، ولم يتم نشره أو ربطه بحساب Cloudflare.

## التصميم الأمني المستهدف
1. واجهة الإدارة لا تحمل GitHub tokens أو Cloudflare secrets.
2. Worker API مستقل على عنوان `workers.dev`؛ لا يتطلب شراء نطاق خاص.
3. بعد النشر الأولي المضبوط، يجب تفعيل Cloudflare Access على **Worker بالكامل** مع اختيار **All traffic** لحماية عنوان الإنتاج والمعاينات.
4. السماح ببريد المدير الوحيد فقط، ومنع أي نطاق بريد أو مستخدمين آخرين.
5. Worker يتحقق مستقلاً من توقيع Access JWT وissuer وaudience وبريد المدير.
6. GitHub access محدود بمستودع Joeydz09/Joebooks فقط، وتُحفظ بيانات الاعتماد في أسرار الخادم، مع Contents Read-only في هذه المرحلة.
7. القراءة من main أولاً، ثم التعديلات المستقبلية على فرع مستقل.
8. كل تغيير يعرض كمعاينة وdiff قبل إنشاء Pull Request.
9. لا دمج ولا نشر إلى الموقع الرسمي قبل موافقة المدير الصريحة.
10. نسخ احتياطية وسجل تدقيق قبل/بعد كل عملية كتابة.
11. حذف سجل الكتاب لا يحذف كائن R2 تلقائياً.
12. إبقاء تكامل preview/maktabati-integration.js دون تغيير.

## مراحل التنفيذ التالية
- مراجعة نموذج الواجهة.
- نشر Worker منفصل بعد تجهيز أسراره، ثم تفعيل Cloudflare Access على All traffic ببريد المدير الوحيد.
- اختبار الرفض دون تسجيل دخول ومع بريد غير مصرح، ثم اختبار القراءة بحساب المدير.
- ربط واجهة الإدارة بالـ API بعد نجاح اختبارات الحماية.
- مطابقة بيانات GitHub والتحقق من اختلاف أعداد السجلات قبل أي مزامنة.
- إضافة عمليات الكتب والمحتوى لاحقاً مع تحقق schema ونسخ احتياطي وdiff.
- اختبارات أمنية ووظيفية، ثم طلب موافقة منفصل قبل أي نشر رسمي.

## ملاحظة النشر
لا تدمج هذا الفرع في main ولا تنشر لوحة الإدارة للعامة. هذا الفرع مخصص للمراجعة والتطوير فقط. لا تُفعّل API أو تستخدمها قبل تفعيل Access والتحقق من أن الوصول مقصور على المدير.
